# ASOSINT Content Guidelines

> Last Updated: August 2026

---

# Purpose

This document defines the content standards for ASOSINT.

Every article, guide, tutorial, tool description, glossary entry, and educational resource should follow these guidelines.

The goal is to create high-quality, trustworthy, and accessible educational content for everyone.

---

# Mission

Our mission is simple:

Help people verify before they trust.

Every piece of content should help users:

- Learn
- Verify
- Stay Safe
- Think Critically
- Make Better Digital Decisions

---

# Target Audience

ASOSINT is written for everyone.

Including:

- Students
- Parents
- Teachers
- Journalists
- Researchers
- Developers
- Government Employees
- Business Owners
- Security Professionals
- General Internet Users

Avoid assuming technical knowledge.

---

# Writing Style

Write like a knowledgeable teacher.

Not like:

- Academic papers
- Marketing copy
- News articles

Be:

- Clear
- Friendly
- Practical
- Professional
- Honest

---

# Tone

Every article should feel:

Helpful

Educational

Trustworthy

Evidence-based

Respectful

Calm

Never:

Fearmongering

Sensational

Clickbait

Overly technical

---

# Language

Primary languages:

English

অসমীয়া (Assamese)

Both languages are equally important.

---

# Translation Policy

Every important page should exist in:

English

Assamese

If translation is unavailable:

Clearly indicate:

"Translation coming soon."

Never silently fall back to another language.

---

# Reading Level

Write for approximately:

Grade 8–10 reading level.

Explain technical concepts simply.

Avoid unnecessary jargon.

---

# Explain Acronyms

Always explain the first occurrence.

Example:

OSINT (Open Source Intelligence)

LLM (Large Language Model)

DNS (Domain Name System)

After that, abbreviations are acceptable.

---

# Article Structure

Every article should follow this structure:

1. Title

2. Summary

3. Why It Matters

4. Main Content

5. Examples

6. Best Practices

7. Common Mistakes

8. FAQs

9. Related Articles

10. Related Tools

11. Sources

---

# Titles

Keep titles descriptive.

Good

How to Detect AI-Generated Images

What Is Voice Cloning?

How Phishing Attacks Work

Avoid

Everything You Need To Know

Ultimate Guide

Secrets

Must Read

---

# Headings

Use a logical hierarchy.

H1

H2

H3

Avoid skipping heading levels.

---

# Paragraphs

Keep paragraphs short.

Prefer:

2–5 sentences.

Avoid long walls of text.

---

# Lists

Use lists whenever appropriate.

Especially for:

Steps

Features

Warnings

Examples

Best Practices

---

# Images

Every image should have a purpose.

Avoid decorative images.

Prefer:

Diagrams

Illustrations

Screenshots

Flowcharts

Annotated examples

---

# Examples

Whenever possible:

Show real-world examples.

Explain:

Why it is safe.

Why it is dangerous.

How to verify it.

---

# Warnings

Use warning blocks for:

Scams

Fraud

Fake websites

Malware

Sensitive topics

Warnings should educate—not scare.

---

# Tool Pages

Every tool page should include:

Overview

Purpose

When to Use

How It Works

Privacy Information

Limitations

FAQs

Related Resources

---

# Internal Linking

Every article should link to:

Related Articles

Related Tools

Relevant Categories

Glossary Terms

Never leave pages isolated.

---

# External Sources

Prefer authoritative sources.

Examples:

Government agencies

Academic institutions

Standards organizations

Official documentation

Well-established security organizations

Avoid citing unreliable or anonymous sources.

---

# AI Content Policy

AI may assist with drafting.

Every AI-generated article must be:

Reviewed

Fact-checked

Edited

Verified

Humans remain responsible for published content.

---

# Fact Checking

Before publishing:

Verify facts.

Verify links.

Verify screenshots.

Verify examples.

Verify dates.

Accuracy is more important than speed.

---

# SEO

Write for humans first.

Search engines second.

Avoid:

Keyword stuffing

Hidden text

Artificial repetition

Use natural language.

---

# Accessibility

Every article should:

Use descriptive headings.

Describe images.

Avoid color-only explanations.

Use readable formatting.

Support screen readers.

---

# Glossary

When introducing advanced terms:

Link to the glossary.

Help beginners learn naturally.

---

# Code Examples

If code is included:

Use syntax highlighting.

Explain what the code does.

Avoid unexplained snippets.

---

# Updates

Technology changes quickly.

Review important articles regularly.

Update:

Screenshots

Links

Examples

Recommendations

Mark major updates with:

"Last Updated"

---

# Editorial Principles

Every article should answer:

What is it?

Why does it matter?

How does it work?

How can someone stay safe?

What should they do next?

---

# Final Principle

Every article should leave readers more informed, more confident, and better equipped to make safe decisions online.

If a reader finishes an article and still feels confused, the article is not complete.
